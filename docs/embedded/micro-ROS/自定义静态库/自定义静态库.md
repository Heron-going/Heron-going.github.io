# 自定义静态库

## 官方资料

1. [自定义静态库官方教程](https://micro.vulcanexus.org/docs/tutorials/advanced/create_custom_static_library/)
2. [STM32CubeMX 构建工具（Humble 分支）](https://github.com/micro-ROS/micro_ros_stm32cubemx_utils/tree/humble)

## 实用性

在前文的 [详细配置指南](../详细配置指南/详细配置指南.md) 中，我们已经使用 Docker 编译出了 `libmicroros.a`。如果需要修改节点数量、增加发布者，或者将同一套通信代码移植到另一块开发板，就需要进一步了解这个静态库是如何配置和生成的。

**自定义静态库主要涉及两类配置：**

| 配置文件 | 负责的内容 | 本文中的例子 |
| :--- | :--- | :--- |
| `toolchain.cmake` | 指定交叉编译器和目标芯片的编译参数 | Cortex-M4、Thumb 指令、硬件浮点 ABI |
| `colcon.meta` | 为不同软件包传入 CMake 参数，选择功能并配置资源上限 | 自定义传输、最多 2 个发布者和 2 个订阅者 |

前文的 Docker 工具已经封装了这两部分。本篇先介绍官方的独立构建流程，再说明如何把配置用回现有工程。

本文沿用前文的 **ROS 2 Humble、STM32F4、FreeRTOS** 环境。下面的芯片参数适用于前文使用的 Cortex-M4 + FPU 配置，换板时需要核对工程实际参数。

---

## 准备编译环境

以下命令均在 **WSL** 中执行。

这里假设已经按照前文完成 `~/uros_ws` 中 `micro_ros_setup` 的安装。另建 `~/uros_static_ws`，用于本篇的静态库构建：

```bash
source /opt/ros/humble/setup.bash
source ~/uros_ws/install/local_setup.bash

mkdir -p ~/uros_static_ws
cd ~/uros_static_ws

ros2 run micro_ros_setup create_firmware_ws.sh generate_lib

touch my_custom_toolchain.cmake my_custom_colcon.meta
```

`generate_lib` 用于准备静态库的源码工作空间。创建后，后面的配置文件和编译命令都在 `~/uros_static_ws` 中操作。

## 配置交叉编译工具链

### 编写 `my_custom_toolchain.cmake`

将以下内容写入刚才创建的文件：

```cmake
# 目标是微控制器，不是运行构建命令的 Linux 主机。
set(CMAKE_SYSTEM_NAME Generic)
set(CMAKE_SYSTEM_PROCESSOR arm)
set(CMAKE_TRY_COMPILE_TARGET_TYPE STATIC_LIBRARY)

# 从 PATH 查找交叉编译器，也可以改成 WSL 中的绝对路径。
set(CMAKE_C_COMPILER arm-none-eabi-gcc)
set(CMAKE_CXX_COMPILER arm-none-eabi-g++)

# 与 STM32 工程的 CPU、指令集和浮点 ABI 保持一致。
set(MCU_FLAGS "-mcpu=cortex-m4 -mthumb -mfpu=fpv4-sp-d16 -mfloat-abi=hard")
set(COMMON_FLAGS "${MCU_FLAGS} -ffunction-sections -fdata-sections")

# 沿用 STM32CubeMX Humble 工具链中的兼容设置。
set(PORT_FLAGS "-DCLOCK_MONOTONIC=0 -D'__attribute__(x)='")

set(CMAKE_C_FLAGS_INIT "-std=c11 ${COMMON_FLAGS} ${PORT_FLAGS}")
set(CMAKE_CXX_FLAGS_INIT
    "-std=c++14 ${COMMON_FLAGS} ${PORT_FLAGS} -fno-exceptions -fno-rtti")
set(__BIG_ENDIAN__ 0)
```

其中，`CMAKE_TRY_COMPILE_TARGET_TYPE` 设为 `STATIC_LIBRARY`，让 CMake 在检查编译器时不必先链接出一个依赖启动文件、链接脚本的可执行程序。相关机制可参考 [CMake 交叉编译说明](https://cmake.org/cmake/help/latest/manual/cmake-toolchains.7.html#cross-compiling)。

`PORT_FLAGS` 参考了 [STM32CubeMX Humble 工具链](https://github.com/micro-ROS/micro_ros_stm32cubemx_utils/blob/humble/microros_static_library/library_generation/toolchain.cmake)。其中 `__attribute__` 的宏会屏蔽 GCC 属性，属于该移植方案的兼容处理，但要论具体发挥多大的作用，笔者还需深入研究。

### 必须核对的硬件参数

| 参数 | 含义 | 需要注意的地方 |
| :--- | :--- | :--- |
| `-mcpu=cortex-m4` | 为 Cortex-M4 生成代码 | 官方教程演示的是 Cortex-M3，本文按前文工程调整 |
| `-mthumb` | 使用 Thumb 指令集 | 与 STM32 工程保持一致 |
| `-mfpu=fpv4-sp-d16` | 指定目标浮点单元 | 应根据实际芯片和工程配置选择 |
| `-mfloat-abi=hard` | 使用硬件浮点调用约定 | 静态库、应用及其依赖库的 ABI 必须兼容 |

**尤其注意浮点 ABI**：硬浮点与软浮点 ABI 不能直接混合链接。如果应用使用 `hard`，静态库却使用 `soft` 或 `softfp`，就可能出现 `uses VFP register arguments` 等链接错误。

## 配置 `colcon.meta`

### 配置示例

将以下内容写入 `my_custom_colcon.meta`。

```json
{
  "names": {
    "tracetools": {
      "cmake-args": [
        "-DTRACETOOLS_DISABLED=ON",
        "-DTRACETOOLS_STATUS_CHECKING_TOOL=OFF"
      ]
    },
    "rosidl_typesupport": {
      "cmake-args": [
        "-DROSIDL_TYPESUPPORT_SINGLE_TYPESUPPORT=ON"
      ]
    },
    "rcl": {
      "cmake-args": [
        "-DBUILD_TESTING=OFF",
        "-DRCL_COMMAND_LINE_ENABLED=OFF",
        "-DRCL_LOGGING_ENABLED=OFF"
      ]
    },
    "rcutils": {
      "cmake-args": [
        "-DENABLE_TESTING=OFF",
        "-DRCUTILS_NO_FILESYSTEM=ON",
        "-DRCUTILS_NO_THREAD_SUPPORT=ON",
        "-DRCUTILS_NO_64_ATOMIC=ON",
        "-DRCUTILS_AVOID_DYNAMIC_ALLOCATION=ON"
      ]
    },
    "microxrcedds_client": {
      "cmake-args": [
        "-DUCLIENT_PIC=OFF",
        "-DUCLIENT_PROFILE_UDP=OFF",
        "-DUCLIENT_PROFILE_TCP=OFF",
        "-DUCLIENT_PROFILE_DISCOVERY=OFF",
        "-DUCLIENT_PROFILE_SERIAL=OFF",
        "-DUCLIENT_PROFILE_STREAM_FRAMING=ON",
        "-DUCLIENT_PROFILE_CUSTOM_TRANSPORT=ON"
      ]
    },
    "rmw_microxrcedds": {
      "cmake-args": [
        "-DRMW_UXRCE_TRANSPORT=custom",
        "-DRMW_UXRCE_MAX_NODES=1",
        "-DRMW_UXRCE_MAX_PUBLISHERS=2",
        "-DRMW_UXRCE_MAX_SUBSCRIPTIONS=2",
        "-DRMW_UXRCE_MAX_SERVICES=0",
        "-DRMW_UXRCE_MAX_CLIENTS=0",
        "-DRMW_UXRCE_MAX_HISTORY=4",
        "-DRMW_UXRCE_STREAM_HISTORY=4"
      ]
    }
  }
}
```

基础裁剪项参考 [Humble 的 `colcon.meta`](https://github.com/micro-ROS/micro_ros_stm32cubemx_utils/blob/humble/microros_static_library/library_generation/colcon.meta)。这里将发布者和订阅者上限各设为 2，关闭未使用的 Service 和 Client，并显式设置可靠流历史槽位数。**这些是本文示例值，读者可以按需修改，但必须满足各参数的取值要求。**

其中，`RMW_UXRCE_STREAM_HISTORY` 必须为 **2 的幂**，例如 `4、8、16`；`RMW_UXRCE_MAX_HISTORY` 没有这个限制。参数区别和实际构建报错见 [中间件配置](../中间件配置/中间件配置.md)。

## 编译并检查产物

这里用我们上篇文章的自定义消息。

回到刚才的工作目录，执行：

```bash
cd ~/uros_static_ws
mkdir -p ~/uros_static_ws/firmware/mcu_ws/extra_packages

cp -a ~/uros_ws/src/my_custom_msgs \
  ~/uros_static_ws/firmware/mcu_ws/extra_packages/
cd ~/uros_static_ws/firmware/mcu_ws
colcon list | grep my_custom_msgs
```

执行最后一条命令有输出后：

```
cd ~/uros_static_ws

ros2 run micro_ros_setup build_firmware.sh \
  "$(pwd)/my_custom_toolchain.cmake" \
  "$(pwd)/my_custom_colcon.meta"
```

这里使用绝对路径，是因为构建脚本会切换到内部源码目录。编译完成后，检查以下产物：

```text
uros_static_ws/
├── my_custom_toolchain.cmake
├── my_custom_colcon.meta
└── firmware/
    └── build/
        ├── libmicroros.a
        └── include/
```

`libmicroros.a` 提供已编译的实现，`include` 提供与该次构建配套的头文件。两者应一起更新到 STM32 工程中。
