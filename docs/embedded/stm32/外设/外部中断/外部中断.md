# STM32 外部中断

外部设备可以通过引脚电平变化通知 STM32。例如，按键被按下、传感器数据准备完成、限位开关动作，都可以产生一个需要处理的信号。**GPIO 外部中断让 CPU 在信号满足触发条件时进入处理函数，处理结束后继续原来的程序。**

## 外部中断与其他中断

日常说的“外部中断”，通常指外部引脚经 EXTI 触发的中断。在 Cortex-M 内核文档中，“外部”则以 CPU 内核为边界，TIM、USART 等片上外设产生的 IRQ 也属于内核外部中断。

| 来源 | 常见情况 | 与 EXTI 的关系 |
| --- | --- | --- |
| GPIO 引脚 | 按键、传感器通知、限位信号 | 通常通过 EXTI 检测电平变化 |
| 片上外设 | 定时器更新、串口收到数据、DMA 完成传输 | 常规中断通常由外设直接向 NVIC 请求，部分唤醒信号会经过 EXTI |
| 内核异常 | SysTick、SVC、PendSV、HardFault | 由内核异常机制管理 |

EXTI 也可以接收片内信号，例如某些芯片上的电压监测、比较器或 RTC 信号。它实际连接哪些来源，取决于芯片的设计。

## GPIO 到 CPU 的完整通路

> 外部信号变化 → GPIO 输入 → 端口映射 → EXTI 检测并发出请求 → NVIC 管理请求 → CPU 进入中断入口 → 软件处理 → 异常返回

这些模块各自承担一部分工作。

| 模块 | 负责什么 |
| --- | --- |
| GPIO | 接收引脚电平，提供数字输入；上下拉用于确定外部未驱动时的默认电平 |
| 端口映射 | 选择某条 EXTI 线接收哪个 GPIO 端口的信号 |
| EXTI | 对 GPIO 信号检测指定边沿，记录挂起状态，并按配置产生中断请求或事件 |
| NVIC | 控制 IRQ 的使能、挂起和优先级，管理请求的响应次序与抢占关系 |
| CPU | 保存必要现场，按照向量表进入处理函数，在异常返回时恢复现场 |
| 中断处理软件 | 识别来源、清除相应标志、保存必要数据或通知后续任务 |

EXTI 常被称为“外部中断和事件控制器”，部分系列文档使用“扩展中断和事件控制器”。NVIC 的全称是 Nested Vectored Interrupt Controller，即“嵌套向量中断控制器”。

一条 GPIO 中断通路要正常工作，需要输入与映射正确、触发条件匹配、EXTI 中断通路开放、对应 NVIC 通道使能，并且 CPU 当前允许响应。中断优先级还会影响它何时执行。

## 上升沿 下降沿与双边沿

GPIO 外部中断常用的触发条件是边沿，也就是电平发生变化的瞬间。

| 触发条件 | 检测的变化 | 典型用途 |
| --- | --- | --- |
| 上升沿 | 低电平 → 高电平 | 检测高有效信号的到来 |
| 下降沿 | 高电平 → 低电平 | 检测低有效信号的到来 |
| 双边沿 | 上升沿和下降沿 | 同时关注信号的建立与撤销 |

例如，上拉输入的按键松开时为高电平，按下接地后变低，可以选择下降沿检测按下。若按键采用下拉输入，按下后接到高电平，则可以选择上升沿。

**上下拉确定默认电平，边沿选择确定何时触发。** 两者需要与外部电路配合。

在边沿触发模式下，信号稳定保持高或低都不会产生新的边沿请求。机械按键的触点会抖动，一次动作可能形成多个边沿，需要通过硬件或软件消抖，把多次电气变化识别为一次按键动作。

## 引脚 中断线与 IRQ 通道

这三个名称描述不同层次。

| 名称 | 含义 |
| --- | --- |
| GPIO 引脚 | 芯片连接外部电路的输入端，例如 PA0、PB0 |
| EXTI 线 | EXTI 内部接收和处理信号的通道，例如 EXTI0 |
| IRQ 通道 | NVIC 管理的中断请求通道，拥有对应的优先级和向量入口 |

许多 STM32 将 GPIO 的 0～15 号引脚分别映射到 EXTI0～EXTI15。同一个引脚序号的不同端口共用一个选择位置，例如 PA0、PB0、PC0 都可以作为 EXTI0 的输入，但在这种映射结构下，同一时刻只能选一个端口。

**多条 EXTI 线也可能共用一个 IRQ 通道。** 当这个通道进入中断时，处理函数需要查看各条线的挂起标志，才能确定来源。若多条线同时挂起，应按设计分别处理。共享通道中的这些线使用同一组 NVIC 优先级。

“引脚映射到哪条线”和“哪些线合用一个 IRQ”是两次不同的连接关系。换芯片时，需要分别查 GPIO 映射表和中断向量表。

## NVIC 的优先级与中断嵌套

NVIC 决定待处理请求的先后，以及一个中断能否打断当前执行。对于通常讨论的可配置 IRQ 优先级，**数值越小，优先级越高**。

在支持优先级分组的内核上，可用的优先级位可以分配为两部分。

| 类型 | 决定什么 |
| --- | --- |
| 抢占优先级 | 是否可以打断正在执行的另一个中断 |
| 子优先级 | 抢占优先级相同时，多个待处理请求先响应哪个 |

假设中断 A 的抢占优先级高于 B，B 执行期间 A 到来，就可能先执行 A，再恢复 B，这就是中断嵌套。抢占优先级相同的中断互相不能抢占，子优先级只影响等待期间的排序。

优先级分组是内核上的统一配置，可用位数由芯片实现决定。Cortex-M0/M0+ 不支持上述抢占优先级与子优先级的分组方式，因此不能把某个系列的位数、分组数直接套到所有 STM32 上。

## CPU 怎样进入中断处理函数

**中断向量表保存异常与中断处理函数的入口地址。** 工程的启动文件通常定义这张表，编译链接后，相应表项引用的就是实际处理函数地址。

CPU 接受中断请求后，由硬件完成必要的现场保存，再依据中断对应的向量表项切换执行位置。处理结束时，异常返回机制恢复被打断的上下文。向量表的定位与重定位能力随内核和芯片实现而异。

在使用 HAL 的工程中，处理过程常包含以下几层。

1. **中断入口函数**是向量表指向的函数，由 CPU 进入。
2. **HAL 处理函数**由入口中的代码调用，检查来源并按库的实现处理标志。
3. **用户回调函数**由 HAL 调用，用于执行用户逻辑。

用户回调仍处于这次中断的执行过程中。它占用的时间也属于中断处理时间。具体有几层调用、是否区分上升沿和下降沿回调，取决于系列和 HAL 版本。

## 挂起状态与清除标志

“挂起”表示中断请求已经被记录，等待响应。“活动”表示处理程序已经进入且尚未完成异常返回，其中也包括被更高优先级中断暂时打断的情况。

GPIO 中断处理中，需要关注两层状态。

| 所在位置 | 记录的内容 | 处理时的含义 |
| --- | --- | --- |
| EXTI 挂起标志 | 某条线检测到了符合条件的变化 | 用来判断具体来源，并按该系列规定清除 |
| NVIC 挂起状态 | 某个 IRQ 有待处理请求 | 影响内核是否继续响应这个通道 |

清除 NVIC 的挂起状态后，如果 EXTI 一侧的请求仍然存在，IRQ 可能再次挂起。因此，中断服务需要处理实际请求源的标志。部分系列共用一个挂起标志，另一些系列分别记录上升沿和下降沿。

挂起位只能表示“有请求”。在标志尚未清除时连续到来的同类边沿，可能合并成一次挂起状态，不能据此还原完整的脉冲次数。高速计数或精确测量边沿时间时，通常要考虑定时器计数或输入捕获等硬件功能。

## 中断 事件与低功耗唤醒

EXTI 可以产生中断请求，也可以产生事件，这两种输出有不同用途。

| 输出 | 主要作用 | 是否自动进入中断函数 |
| --- | --- | --- |
| 中断请求 | 通知 NVIC，安排 CPU 执行处理程序 | 满足响应条件时会进入 |
| 事件 | 向内核或芯片支持的硬件通路传递事件通知，例如使等待事件的内核继续执行 | 单独的事件通知不会自动进入中断函数 |

中断和事件的通路通常可以分别配置。EXTI 还参与某些低功耗模式的唤醒，但哪些信号能唤醒哪种模式，需要结合电源管理模块和芯片手册判断。某种模式下可以作为普通中断的引脚，并不自动具备所有低功耗模式的唤醒能力。
